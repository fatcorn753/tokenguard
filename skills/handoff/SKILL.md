# handoff

目的: 費用の大半は長い会話の文脈を毎回読み直すことにかかる。作業の区切りで要点だけを書き出し、
小さな文脈の新しい会話で続ける。compact より情報を選んで残せるので、品質を落とさずに済む。

## 書き出し(引数なし、または「書く」)

1. `~/.claude/handoffs/` に `YYYY-MM-DD-HHMM-<短い英語slug>.md` を作る。日時は `date +%Y-%m-%d-%H%M` で取る。
2. 次の見出しで書く。合計 150 行以内に収める。会話を読み返さず、覚えている事実だけを書く。
   - **目的**: ユーザーが最終的に欲しいもの(ユーザーの言葉で 1〜3 行)
   - **場所**: リポジトリの絶対パス、ブランチ、関係するファイル(`path:line` の形)
   - **済んだこと**: 変更点とコミット(ハッシュ付き)
   - **確かめたこと / 未確認**: 実施した検証と、まだ検証していない項目を分けて書く
   - **決めたこと**: 設計判断とその理由。ユーザーが却下した案も書く(同じ案を再提案しないため)
   - **落とし穴**: 試して失敗したことと、その原因
   - **次の一手**: 最初に実行するコマンドや、最初に開くファイル
   - **続きの依頼文**: 新しい会話に貼れば、そのまま再開できる 1〜3 行
3. 秘匿情報(トークン・パスワード・個人情報)は書かない。必要なら置き場所だけを書く。
4. 未コミットの変更があれば、その旨とファイル名を「済んだこと」に書く。勝手にコミットはしない。
5. ユーザーへの報告は 3 行までにする。ファイルのパスと、新しい会話の始め方を伝える。
   - デスクトップアプリで `mcp__ccd_session__start_session` を使えるなら、`context: "fresh"` で
     「<パス> の引き継ぎを読んで続ける」という brief の新しい会話を提案する。fork は文脈を丸ごと
     引き継ぐので節約にならない。fork は使わない。
   - CLI なら「`/clear` のあと `/handoff 読込 <パス>`」と伝える。

## 読み込み(「読込 <パス>」、パスを省略したら最新の 1 件)

1. `ls -t ~/.claude/handoffs/*.md | head -1` で対象を決め、Read する。
2. 「未確認」と「次の一手」から始める。書かれている事実のうち、作業の前提になるものは
   `git log -3` や対象ファイルの該当行で確かめる(引き継ぎの後にファイルが変わっていることがある)。
3. 引き継ぎに書かれていないことを探すために、リポジトリ全体を読み直さない。必要なものだけ読む。
